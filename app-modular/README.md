# دليل النسخة المهيكلة معمارياً (microERP Modular Architecture Guide)

مرحباً بك في النسخة المهيكلة معمارياً من نظام **ميكروERP**. تم تفكيك الكود الضخم القديم (~30,000 سطر) إلى هيكل موديولي منظم وموزع هندسياً وفق أحدث معايير هندسة البرمجيات النظيفة (Clean Architecture) ونظام الوحدات المستقلة الموجهة بالمجال (Domain-Driven Submodules).

## 🛠️ أوامر التطوير وضمان الجودة (Developer CLI Commands)

تم تجهيز المشروع بمجموعة أدوات متكاملة تضمن أعلى درجات الموثوقية والاستقرار:

| الأمر | الوظيفة | الوصف |
|---|---|---|
| `npm run verify` | التحقق وتجميع الحزمة | تشغيل `build.js` وتجميع الـ 41 ملفاً في `dist/index.html` مع فحص سلامة بناء الجافاسكربت بنسبة 100%. |
| `npm test` | اختبارات الوحدة الآلية | تشغيل حزمة اختبارات Vitest الشاملة على المحرك المالي، الحسابات، الضرائب، الصلاحيات، والعمليات الحسابية. |
| `npm run lint` | فحص جودة ونظافة الكود | تشغيل ESLint (Flat Config) للتحقق من عدم وجود أي متغيرات غير معرفة أو مهملة عبر كامل المشروع. |
| `npm start` | تشغيل التطبيق محلياً | تجميع الكود الموديولي وتشغيل نافذة تطبيق سطح المكتب عبر Electron. |
| `npm run build:win` | حزم تطبيق ويندوز | بناء ملف التثبيت ومثبت ويندوز المحمول Portable (.exe). |
| `npm run build:mac` | حزم تطبيق ماك | بناء حزمة نظام macOS بصيغة DMG. |

## 🧪 حزمة الاختبارات الآلية (Automated Test Suite)

تقع حزمة الاختبارات في مجلد `tests/` وتغطي بدقة متناهية كافة العمليات الرياضية والمحاسبية:
* `tests/money.test.js`: دقة التقريب المالي لمنزلتين عشريتين، معالجة مشكلة الفواصل العائمة، وتنسيق العملات.
* `tests/journal.test.js`: التوازن المحاسبي للقيد المزدوج، التحقق من بنود القيود، وتوليد ميزان المراجعة.
* `tests/cogs.test.js`: تكلفة البضاعة المباعة (COGS)، مجمل الربح، هامش الربح، وصافي الأرباح التشغيلية.
* `tests/vat.test.js`: ضريبة القيمة المضافة المصرية (14%)، فصل الضريبة من السعر الشامل، والإقرار الضريبي.
* `tests/permissions.test.js`: التحقق من مصفوفة الصلاحيات (RBAC) والأدوار التنفيذية (Admin, Accountant, Cashier, Tech).
* `tests/numbers.test.js`: تنظيف الأرقام المشرقية والعربية والفارسية، فواصل الكسور، والباركود.

## 🔄 خط أنابيب التكامل المستمر (CI Workflow)

يتضمن المشروع ملف عمل GitHub Actions في [`.github/workflows/ci.yml`](file:///.github/workflows/ci.yml) يتم تشغيله آلياً عند كل عملية رفع (Push) أو طلب دمج (Pull Request) للتأكد من سلامة الكود عبر ثلاث مراحل متتابعة:
1. `npm run verify`
2. `npm run lint`
3. `npm test`

## 🛡️ قواعد الأمان المعمارية الصارمة
1. **مسار البناء الوحيد:** التعديلات البرمجية تتم حصراً في ملفات `app-modular/js/` و `app-modular/css/`. لا تعدّل ملف `app-modular/dist/index.html` يدوياً أبداً لأنه ناتج مُولَّد آلياً.
2. **عزل النطاق العام:** المحركات الحسابية والمالية مصممة لتكون مستقلة عن واجهة المستخدم (DOM-Independent) لتسهيل اختبارها وتطويرها.
3. **التوافق التام مع الخلفية السحابية:** كافة الموديولات ترسل وتستقبل البيانات بصيغ متوافقة 100% مع مخطط جداول Google Sheets وأكواد Google Apps Script.
